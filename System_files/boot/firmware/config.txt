# onboard brcmfmac OFF 2026-07-25: 5GHz interference w/ WFB ch161 + attenuated by enclosure.
# Uplink = external RTL8821CU wlx90de80d824d6. Comment out the next line to restore.
# NOTE: config.txt has NO inline-comment support - a trailing "#..." on the same line is parsed
# as part of the overlay name, so the overlay is SILENTLY IGNORED. That bug was live 07-25..07-26.
# 2026-07-30: was "disable-wifi" - WRONG OVERLAY FOR PI 5. That .dtbo is
# compatible="brcm,bcm2835" and targets mmc/mmcnr; this board is BCM2712 and the
# radio sits on sdio2, so it applied and did nothing (brcmfmac stayed loaded,
# radio live as wlan1 on ch34). disable-wifi-pi5.dtbo is compatible="brcm,bcm2712"
# and targets sdio2, which is the one this board needs.
# VERIFY AFTER REBOOT WITH:  lsmod | grep brcmfmac   (must be EMPTY)
# NOT with "ip link show wlan0" - the iface renamed to wlan1, so that falsely passes.
dtoverlay=disable-wifi-pi5
dtoverlay=uart0
dtoverlay=uart2
dtoverlay=uart3-pi5
dtoverlay=uart4

# 2026-09-05: Waveshare RS485 CAN HAT (rev 2.1, 12 MHz crystal) -> MCP2515 on spi0.0 (CE0=GPIO8),
# INT on GPIO25. Bus is 1 Mbit to match PX4 UAVCAN_BITRATE=1000000 and VESC can_baud_rate=3
# (CAN_BAUD_1M). Purpose: DroneCAN firmware update of the four VESCs (node IDs 10-13).
# NOTE: config.txt has NO inline-comment support - keep the dtoverlay line free of trailing "#".
# NOTE: SPI0 takes GPIO8/9, so dtoverlay=uart3-pi5 (STL-19 lidar, ttyAMA3) loses the pins and
# does not probe. That was ALREADY true before this line - dtparam=spi=on is set at line 12.
# VERIFY AFTER REBOOT WITH:  ip -details link show can0   (must exist)
# NOT with "lsmod | grep mcp251x" alone - the module can load without the device binding.
# 2026-09-06: 10000000 gave "MCP251x didn't enter in conf mode after reset", probe err=110.
# RP1 SPI on the Pi 5 clocks differently from BCM2835; 10 MHz is the MCP2515 ceiling. Trying 1 MHz.
dtoverlay=mcp2515-can0,oscillator=12000000,interrupt=25,spimaxfrequency=1000000
